# 접합부 B: 워크플로 → 배포

- 상태: implemented
- 갱신: 2026-08-23
- 소유: (미정)

## 문제

완성된 워크플로가 배포 단위로 그대로 이어지지 않으면 배포가 별도 구현이 돼요. 그러면 캔버스에서 확인한 결과와 엔드포인트가 돌려주는 결과가 달라질 수 있어요.

## 사용자와 사용 시점

캔버스에서 원하는 결과를 얻은 사용자가 "배포"를 누르는 순간이에요.

## 범위

### 하는 것

- 워크플로 하나를 배포 단위로 바꾸는 형식을 정의해요.
- 저장된 `OperationSpec`과 요청 기본값, payload 스키마를 배포 단위에 함께 보존해요.
- 배포된 엔드포인트가 캔버스와 같은 연산 스펙을 실행하도록 보장해요.

### 안 하는 것

- 배포 후 워크플로를 자동으로 다시 실행하지 않아요.
- 버전 롤백과 배포 이력 관리는 하지 않아요.

## 동작

1. 프로젝트 설정에서 요청 기본값과 payload 스키마를 저장해요.
2. 배포 모달을 열면 API와 MCP 고정 엔드포인트가 동시에 생겨요.
3. API와 MCP는 저장된 `OperationSpec`을 그대로 실행하고, 요청의 `schema`가 있으면 응답 JSON 형식만 덮어써요.

## 계약

`Workflow`는 배포에 필요한 모든 것을 스스로 가져야 해요. 배포 시점에 캔버스 상태를 다시 읽지 않아요. `nodes[]`와 `links[]`의 형식은 [`002-workflow-canvas.md`](002-workflow-canvas.md)가 정해요.

| 필드            | 뜻                                                             |
| --------------- | -------------------------------------------------------------- |
| `nodes[]`       | 데이터 노드와 각 노드의 출처                                    |
| `links[]`       | 노드 사이 연결과 확정된 `OperationSpec`                        |
| `operationSpec`  | 캔버스에서 검증한 GovData 실행 스펙                          |
| `requestData`    | API와 MCP 요청에 사용할 기본 JSON 객체. `filters`는 결과 행 선택에 사용해요. |
| `payloadSchema`  | 결과 `output`을 만들 기본 JSON 스키마                         |

`OperationSpec`은 선언적이어야 해요. 코드 문자열, 임의 표현식, 실행 가능한 필드를 담지 않아요. 캔버스 실행기와 배포 실행기는 같은 실행 함수를 공유해요.

## 인수 기준

- [x] 배포된 엔드포인트가 planner 재실행 없이 캔버스의 `OperationSpec`을 실행해요.
- [x] 배포된 엔드포인트의 결과가 캔버스의 결과 노드와 같은 행 수, 같은 컬럼을 돌려줘요.
- [x] 저장된 payload 스키마 또는 요청의 `schema`가 JSON output에 적용돼요.
- [x] `request.filters`가 결과 컬럼 또는 payload 필드와 연결돼 결과 행을 제한해요.
- [x] `OperationSpec`에 실행 가능한 문자열을 넣으면 스키마 검증에서 막혀요.
- [x] 배포 단위가 워크플로 하나만으로 재현돼요. 외부 상태를 참조하지 않아요.
- [x] 배포 실행도 캔버스와 같은 결과 품질 정지 조건을 적용해요.

## 실패와 정지 조건

| 감지                             | 사용자에게 보이는 것          | 진행 여부   |
| -------------------------------- | ----------------------------- | ----------- |
| 결과 노드가 정지 신호로 멈춘 상태 | 어떤 노드에서 멈췄는지 표시   | 배포 안 함  |
| 실행 결과가 0행, 매칭률 50% 미만, 결측률 20% 초과 | 정지 이유와 관측값 표시 | 오류 응답 |
| 파라미터 타입과 노드 입력 불일치 | 어떤 파라미터가 안 맞는지 표시 | 배포 안 함  |
| 원본 데이터 응답 실패            | 실패한 데이터셋 표시          | 오류 응답   |

## 결정

| 항목                 | 결정                                                   |
| -------------------- | ------------------------------------------------------ |
| 실행 스펙            | 캔버스에서 검증한 `OperationSpec`을 워크플로에 저장해요 |
| 응답 형식            | 표 메타와 `output` JSON 목록을 함께 반환해요           |
| 요청 스키마 우선순위 | 요청 `schema` → 프로젝트 `payloadSchema` 순서예요      |
| MCP 도구             | `query_project` 하나를 HTTP JSON-RPC로 제공해요        |
