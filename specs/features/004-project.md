# ④ 프로젝트

- 상태: agreed
- 갱신: 2026-08-22
- 소유: (미정)

## 문제

파이프는 질문 하나를 발견 · 조립 · 배포로 끌고 가요. 그런데 그 세 단계를 담을 그릇이 없으면 발견에서 받은 제안은 캔버스를 열기 전까지 갈 곳이 없고, 브라우저를 닫으면 사라져요.

공공데이터는 연 단위로 갱신돼요. "같은 조합을 내년에 다시"가 실제 수요인데, 담을 곳이 없으면 매번 질문부터 다시 해야 해요. 일회성 분석은 자산이 되지 못해요.

## 사용자와 사용 시점

질문을 가진 사용자가 작업을 시작할 때 만들고, 중간에 그만뒀다가 다시 열 때 찾아요.

## 범위

### 하는 것

- 프로젝트 목록에서 새 프로젝트를 만들어요.
- 새 프로젝트 모달에서 이름과 설명을 받아요. 설명은 발견 단계에서 사용하는 질문으로 저장해요.
- 만든 프로젝트 목록을 보고 이어서 열어요.
- 프로젝트 안에서 발견 · 조립 · 배포 세 단계를 오가요.
- 프로젝트가 지금 어느 단계인지 보여줘요.
- 프로젝트 이름을 바꾸고 프로젝트를 지워요.

### 안 하는 것

- 공유, 권한, 협업을 하지 않아요. 회원가입이 없어서 소유자를 구분할 수 없어요.
- 버전 기록과 되돌리기를 하지 않아요.
- 폴더와 태그로 정리하지 않아요. 데모 규모에서 목록 하나로 충분해요.
- 한 프로젝트에 워크플로를 여러 개 두지 않아요.

## 동작

1. `/`에서 프로젝트 목록을 봐요.
2. 사용자가 `새 프로젝트`를 누르면 이름과 설명을 받는 모달이 떠요.
3. 이름과 설명을 채워 만들면 설명을 질문으로 저장하고 `/projects/:id`로 이동해요.
4. 프로젝트가 열리고 발견 단계에서 시작해요.
5. 사용자가 단계를 진행하면 프로젝트가 그 결과를 담아요.
6. 목록에서 프로젝트를 다시 열면 마지막 상태 그대로예요.

## 화면

| 경로            | 화면                                                          |
| --------------- | ------------------------------------------------------------- |
| `/`             | 화면 중앙의 프로젝트 목록과 새 프로젝트 버튼                  |
| `/projects/:id` | 카드형 사이드 내비게이션, 작업 바, 캔버스 플레이그라운드      |

- `/`에서 이름과 설명으로 프로젝트를 만들면 바로 `/projects/:id`로 이동해요.
- `/projects/:id`의 사이드 내비게이션은 화면 가장자리에서 16px 떨어진 카드로 보여요. 모서리는 12px이고 진한 테두리를 가져요.
- 프로젝트 내부 사이드 내비게이션은 접을 수 있고, 도구와 단계, 저장만 보여줘요. 프로젝트 설명은 플레이그라운드 위 작업 바에 보여줘요.
- 작업 바에는 프로젝트 이름과 설명, 실행 버튼, 배포 버튼을 보여줘요. 아직 준비되지 않은 실행과 배포는 비활성 상태로 보여줘요.
- 접힌 사이드 내비게이션에서도 아이콘과 `title`로 도구와 저장을 사용할 수 있어요.
- `/`에는 소개 콘텐츠를 두지 않고 프로젝트 목록과 새 프로젝트 버튼만 중앙에 배치해요. 프로젝트는 한 줄씩 읽는 리스트로 보여줘요.
- 데이터는 하이드레이션 뒤에 불러와요. 그전에는 스켈레톤을 보여줘요. 빈 배열로 시작하면 사용자가 "없음"으로 오해해요.

## 프로젝트와 워크플로

한 프로젝트는 워크플로를 정확히 하나 가져요. 둘을 나눠 두는 이유예요.

- 발견 단계의 결과인 `Suggestion`은 캔버스 노드가 되기 전에 존재해요. 워크플로는 아직 비어 있어서 담을 수 없어요.
- 질문은 워크플로보다 오래 살아요. 워크플로를 갈아엎어도 질문은 그대로예요.
- 반복 수요는 워크플로가 아니라 질문 단위로 생겨요.

## 단계는 저장하지 않고 유도해요

프로젝트에 `phase` 필드를 두지 않아요. 내용에서 유도해요. 따로 저장하면 내용과 어긋나고, 어긋났을 때 무엇이 맞는지 알 수 없어요.

| 조건                        | 단계 |
| --------------------------- | ---- |
| 배포가 있어요               | 배포 |
| 워크플로에 캔버스 노드가 있어요 | 조립 |
| 그 외                       | 발견 |

## 저장

프로젝트는 Cloudflare D1의 `projects` 테이블에 저장해요. 회원가입이 없어서 소유자를 구분하지 않고, 배포된 앱에서 열면 누구나 같은 목록을 봐요.

- 브라우저를 바꿔도 프로젝트가 따라와요. 목록은 서버가 돌려주는 값 하나예요.
- 웹은 `POST /api/graphql` 한 곳으로만 읽고 써요. 라우트가 D1을 직접 만지지 않아요.
- 워크플로는 `workflow` 컬럼에 JSON 문자열로 넣어요. D1에서 워크플로 안을 질의하지 않아서 컬럼을 쪼개지 않아요.
- 배포하면 그 시점의 워크플로 스냅샷만 배포 런타임으로 넘어가요. 형식은 [`011-seam-workflow-to-deployment.md`](011-seam-workflow-to-deployment.md)가 정해요.

## 계약

```ts
type ProjectId = string;

interface Project {
  id: ProjectId;
  name: string;
  question: string;
  workflow: Workflow;
  deploymentId: DeploymentId | null;
  createdAt: string;
  updatedAt: string;
}

type ProjectPhase = "discover" | "compose" | "serve";
```

- `Workflow`의 캔버스 형식은 [`002-workflow-canvas.md`](002-workflow-canvas.md)가 정해요. 프로젝트는 캔버스 노드가 하나라도 있는지만 봐요.
- `id`는 ULID 26자 대문자 문자열이에요. 생성 순서로 정렬돼서 목록에 별도 정렬 키가 필요 없어요.
- `createdAt`과 `updatedAt`은 UTC ISO 8601 문자열이에요.
- `name`은 비어 있을 수 없어요. 생성 모달에서 받고 사용자가 바꿀 수 있어요.
- `question`은 비어 있을 수 없어요. 생성 모달의 설명을 저장한 값이고 발견 단계의 입력으로 사용해요.
- D1에서 읽은 행은 도메인 타입으로 단언하지 않고 검증한 뒤 통과시켜요. 검증에 실패한 항목은 목록에서 빼고 뺀 개수를 사용자에게 알려요.

### GraphQL 표면

`phase`와 노드 종류는 GraphQL에서 SCREAMING_CASE, 도메인에서 소문자예요. 두 표기를 아는 곳은 웹의 GraphQL 경계 한 곳뿐이에요.

| 필드                            | 뜻                                                  |
| ------------------------------- | --------------------------------------------------- |
| `Query.projectList`             | 프로젝트 배열과 검증에서 빠진 개수(`droppedCount`)  |
| `Query.project(id)`             | 프로젝트 하나. 없으면 `null`                        |
| `Mutation.createProject`        | 이름과 설명에 해당하는 질문으로 프로젝트를 만들어요    |
| `Mutation.renameProject`        | 이름을 바꿔요                                       |
| `Mutation.saveWorkflow`         | 캔버스 상태를 통째로 덮어써요                       |
| `Mutation.deleteProject`        | 지운 프로젝트 id를 돌려줘요                         |

## 인수 기준

- [ ] 메인 화면에 한 줄 리스트 형태의 프로젝트 목록과 `새 프로젝트` 버튼이 보여요.
- [ ] `새 프로젝트`를 누르면 이름과 설명을 받는 모달이 열려요.
- [ ] 모달에서 취소하거나 Escape를 누르면 프로젝트를 만들지 않고 닫혀요.
- [ ] 이름과 설명을 채워 만들면 프로젝트가 열려요.
- [ ] 새로고침하거나 다른 브라우저에서 열어도 목록에 그대로 있어요.
- [ ] `/projects/:id`로 바로 들어가면 그 프로젝트가 열려요.
- [ ] 프로젝트가 하나도 없으면 무엇을 해야 하는지 알려주는 빈 상태가 보여요.
- [ ] 프로젝트 이름을 바꾸면 목록과 프로젝트 화면 양쪽에 반영돼요.
- [ ] 프로젝트를 지우면 목록에서 사라지고 다시 열리지 않아요.
- [ ] 저장된 행이 깨져 있으면 그 항목만 빠지고 나머지 목록은 보여요.

## 실패와 정지 조건

| 감지                            | 사용자에게 보이는 것                 | 진행 여부 |
| ------------------------------- | ------------------------------------ | --------- |
| D1 바인딩이 없어요              | 저장되지 않는다는 사실과 이유        | 멈춤      |
| D1 쓰기가 실패했어요            | 저장 실패와 다시 시도하는 길         | 멈춤      |
| 저장된 행이 형식에 안 맞아요    | 빠진 항목 수                         | 진행      |
| 워크플로가 캔버스 계약에 안 맞아요 | 저장하지 못했다는 사실과 이유       | 멈춤      |
| 없는 프로젝트를 열었어요        | 없다는 사실과 목록으로 가는 길       | 멈춤      |
