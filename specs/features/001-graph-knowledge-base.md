# ① 그래프 지식 베이스

- 상태: draft
- 갱신: 2026-08-22
- 소유: (미정)

## 문제

사용자의 가장 큰 벽은 "어떤 데이터를 써야 할지 모른다"예요. 포털 검색은 키워드 매칭이라 "쓰레기"로 찾으면 "생활폐기물"을 못 찾아요. 데이터셋 단위 검색으로는 부족하고, 조합을 제안해야 해요.

## 사용자와 사용 시점

질문은 있는데 어떤 데이터로 답할 수 있는지 모르는 사용자가 처음 들어오는 지점이에요.

## 범위

### 하는 것

- 데이터셋별 컬럼을 조사해 LLM이 설명을 붙인 데이터 위키를 만들어요.
- 데이터셋 · 컬럼 · 개념 세 층의 그래프로 인덱싱해요.
- 자연어 질문을 받아 데이터셋 + 컬럼 조합을 제안해요.
- 근거로 실제 데이터셋 카드와 컬럼 설명을 함께 보여줘요.

### 안 하는 것

- 모든 공공 API를 자동 연동하지 않아요. 경북 시군 단위로 조인 가능한 데이터부터 다뤄요.
- 인과 추론을 하지 않아요. 어울리는 조합만 제안해요.

## 동작

1. 데이터셋별로 컬럼을 조사해 LLM이 설명을 붙인 데이터 위키를 만들어요.
2. 컬럼에 개념을 붙이고 데이터셋 · 컬럼 · 개념 세 층으로 인덱싱해요. 노드와 엣지 정의는 [`../product/glossary.md`](../product/glossary.md)의 그래프 모델을 따라요.
3. 사용자가 "~를 하고 싶다"를 입력해요.
4. 질문을 `measure`와 `attribute` 개념에 매칭하고, 거기서 컬럼과 데이터셋으로 역방향 탐색해요.
5. 도달한 데이터셋들이 공유하는 `key` 개념을 조인 키로 확정하고 답해요.
   > "A 데이터의 `a`·`b` 컬럼과 B 데이터의 `c` 컬럼이 어울려요. 조인 키는 시군구 코드예요."
6. 근거로 지나온 경로와 실제 데이터셋 카드, 컬럼 설명을 함께 보여줘요.

## 계약

노드 종류, 엣지 종류, `role`, 식별자 형식은 [`../product/glossary.md`](../product/glossary.md)의 그래프 모델이 소유해요. 이 스펙에서 다시 정의하지 않아요.

출력은 [`010-seam-suggestion-to-canvas.md`](010-seam-suggestion-to-canvas.md)가 정의한 `Suggestion`이에요. 그래프 내부 구조가 바뀌어도 이 형식은 유지해요.

`Suggestion`의 `evidence`는 질문에서 데이터셋까지 지나온 그래프 경로예요. 근거를 따로 만들지 않고 경로를 그대로 보여줘요.

## 인수 기준

- [ ] 키워드가 정확히 일치하지 않는 질문("쓰레기")에도 관련 데이터셋("생활폐기물")을 제안해요.
- [ ] 제안이 데이터셋 이름만이 아니라 실제 컬럼 이름을 포함해요.
- [ ] 제안마다 조인 키가 명시되고, 그 조인 키가 두 데이터셋 모두에서 어떤 컬럼에 대응하는지 보여요.
- [ ] 컬럼명이 서로 다른 두 데이터셋("시군구명", "행정구역코드")이 같은 `key` 개념으로 묶여요.
- [ ] 제안의 근거로 실제 데이터셋 카드와 컬럼 설명을 볼 수 있어요.
- [ ] 제안을 그대로 캔버스로 보낼 수 있어요.

## 실패와 정지 조건

| 감지                        | 사용자에게 보이는 것              | 진행 여부      |
| --------------------------- | --------------------------------- | -------------- |
| 공유하는 `key` 개념이 없음  | 조인할 수 없는 이유를 표시        | 제안 안 함     |
| 카탈로그에 컬럼 정보가 없음 | 해당 데이터셋을 후보에서 제외한 표시 | 나머지로 제안 |
| `MEANS` confidence가 낮음   | 불확실한 매핑임을 표시            | 제안하되 표시  |
