# 스펙 템플릿

`features/` 아래에 복사해서 사용해요. 해당 없는 절은 지우지 말고 "없어요"라고 적어요. 빈 절은 아직 생각하지 않았다는 신호예요.

```markdown
# <스펙 이름>

- 상태: draft
- 갱신: YYYY-MM-DD
- 소유: <이름>

## 문제

사용자가 지금 무엇을 못 하는지 한두 문단으로 적어요. 해결책을 적지 않아요.

## 사용자와 사용 시점

누가 어떤 상황에서 이 기능을 쓰는지 적어요.

## 범위

### 하는 것

- 데모에서 실제로 동작해야 하는 항목을 적어요.

### 안 하는 것

- 의도적으로 빼는 항목과 이유를 적어요.

## 동작

사용자가 보는 순서대로 번호를 붙여 적어요. 화면 이름이 아니라 일어나는 일을 적어요.

## 계약

이 스펙이 밖으로 노출하는 타입, 스키마, 엔드포인트를 적어요. 앞뒤 단계와 주고받는 형식은 반드시 여기에 적어요.

## 인수 기준

- [ ] 관찰 가능한 결과로 적어요. "정확하다" 대신 "행 수와 제외 사유가 화면에 보인다"처럼 적어요.

## 실패와 정지 조건

| 감지 | 사용자에게 보이는 것 | 진행 여부 |
| ---- | -------------------- | --------- |
|      |                      |           |

## 미정

| 질문 | 정하는 시점 | 정할 사람 |
| ---- | ----------- | --------- |
|      |             |           |

## 근거

- `research/...` 또는 참고한 스펙 경로를 적어요.
```
