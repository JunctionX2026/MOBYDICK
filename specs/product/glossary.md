# 용어

- 상태: agreed
- 갱신: 2026-08-22

코드 식별자와 문서 용어를 여기에 맞춰요. 같은 것을 두 이름으로 부르지 않아요.

## 도메인

| 용어           | 코드 식별자    | 뜻                                                                 |
| -------------- | -------------- | ------------------------------------------------------------------ |
| 프로젝트       | `Project`      | 질문 하나와 그 질문이 만든 워크플로를 담는 지속 단위예요.          |
| 데이터셋       | `Dataset`      | 공공데이터의 배포 단위이자 호출 단위예요. 컬럼 목록을 가져요.      |
| 컬럼           | `Column`       | 데이터셋 안의 필드예요. 원본 표기를 그대로 보존해요.               |
| 개념           | `Concept`      | 표현과 무관한 의미 단위예요. 서로 다른 컬럼명을 하나로 묶어요.     |
| 데이터 위키    | `DatasetWiki`  | 컬럼에 LLM이 붙인 설명 모음이에요. 개념을 붙이는 재료예요.         |
| 제안           | `Suggestion`   | 질문에 대해 그래프가 답하는 데이터셋 + 컬럼 조합이에요. 접합부 A의 단위예요. |
| 노드           | `CanvasNode`   | 캔버스에 놓인 데이터 하나예요. 그래프 노드와 다른 것이에요.        |
| 링크           | `CanvasLink`   | 노드 사이 연결이에요. 자연어 의도를 가져요.                        |
| 연산 스펙      | `OperationSpec`| 링크의 자연어를 AI가 바꾼 선언적 연산 정의예요. 실행은 코드가 해요. |
| 워크플로       | `Workflow`     | 노드와 링크 전체예요. 접합부 B의 단위예요.                         |
| 배포           | `Deployment`   | 워크플로를 고정 엔드포인트로 노출한 결과예요.                      |
| 정지 신호      | `Halt`         | 시스템이 감지해 실행을 멈추는 조건이에요.                          |

`Dataset`, `Column`, `Concept`는 그래프 노드이고 `CanvasNode`는 캔버스 노드예요. 문서에서 그냥 "노드"라고 쓰지 않고 어느 쪽인지 밝혀요.

## 그래프 모델

그래프는 `Dataset` - `Column` - `Concept` 세 층으로 구성해요. 하나의 층만으로는 세 가지를 동시에 만족할 수 없어요.

- 데이터셋만 두면 "어떤 컬럼을 봐야 하는지"에 답하지 못하고 조인 키를 정하지 못해요.
- 컬럼만 두면 "쓰레기"와 "생활폐기물"의 매칭이 컬럼명 문자열 유사도에 갇히고, 조인 후보 판정이 컬럼 쌍 전수 비교가 돼요.
- 개념만 두면 근거로 보여줄 실제 데이터셋 카드와 실제 컬럼 이름이 사라지고 호출 단위를 정하지 못해요.

### 노드

| 노드      | 무엇을 나타내나          | 생성 방법                       | 결정성 |
| --------- | ------------------------ | ------------------------------- | ------ |
| `Dataset` | 배포 · 호출 단위         | 카탈로그를 그대로 옮겨요        | 결정적 |
| `Column`  | 원본 표기의 필드         | 카탈로그를 그대로 옮겨요        | 결정적 |
| `Concept` | 표현과 무관한 의미 단위  | 데이터 위키를 근거로 LLM이 붙여요 | 확률적 |

`Concept`는 `role`을 하나 가져요. 조인 판정과 제안 생성이 이 값으로 갈려요.

| `role`      | 뜻                       | 예                              |
| ----------- | ------------------------ | ------------------------------- |
| `key`       | 조인축이 되는 개념       | 시군구, 기준 연도               |
| `measure`   | 세어지거나 재어지는 값   | 생활폐기물 배출량, 인구         |
| `attribute` | 분류하거나 설명하는 값   | 업종, 처리 방식                 |

### 엣지

| 엣지             | 방향                | 생성 방법                   | 결정성 |
| ---------------- | ------------------- | --------------------------- | ------ |
| `HAS_COLUMN`     | `Dataset` → `Column` | 카탈로그                    | 결정적 |
| `MEANS`          | `Column` → `Concept` | 임베딩으로 후보를 좁히고 LLM이 판정해요 | 확률적 |
| `CONVERTIBLE_TO` | `Concept` → `Concept` | 단위 정의에서 환산식을 가져요 | 결정적 |
| `RELATED_TO`     | `Concept` - `Concept` | LLM 판정                    | 확률적 |

`MEANS`는 `confidence`와 판정 근거를 함께 가져요. 확률적 엣지는 사용자에게 근거를 보여줄 수 있어야 해요.

### 조인 가능은 엣지가 아니라 경로예요

`조인 가능` 엣지를 만들지 않아요. 두 데이터셋이 같은 `key` 개념에 닿는 컬럼을 각각 가지면 조인 가능해요.

```
Dataset A -HAS_COLUMN-> Column "시군구명"     -MEANS-> Concept(시군구, role=key)
Dataset B -HAS_COLUMN-> Column "행정구역코드" -MEANS-> Concept(시군구, role=key)
```

이렇게 두는 이유예요.

- 컬럼 쌍 전수 비교가 컬럼당 개념 매핑 한 번으로 줄어요. 데이터셋이 늘어도 비용이 제곱으로 늘지 않아요.
- 데이터셋을 추가할 때 기존 엣지를 다시 계산하지 않아요.
- 왜 조인되는지를 개념 이름으로 설명할 수 있어서 그 경로가 곧 제안의 근거가 돼요.

### 질문에서 제안까지

1. 질문을 `measure`와 `attribute` 개념에 매칭해요. 여기서 "쓰레기"가 생활폐기물 개념에 닿아요.
2. `MEANS`를 역방향으로 타고 컬럼과 데이터셋에 도달해요.
3. 도달한 데이터셋들이 공유하는 `key` 개념을 찾아요. 이게 조인 키예요.
4. 데이터셋, 컬럼, 조인 키와 지나온 경로를 `Suggestion`으로 만들어요. 경로가 곧 `evidence`예요.

### 정규화가 붙는 자리

`key` 개념은 정규 형식을 하나만 가져요. 시군구의 정규 형식은 행정표준코드 5자리예요. `MEANS` 엣지가 컬럼 값을 그 형식으로 바꾸는 방법(코드 그대로, 이름에서 코드 조회, 접두 절단)을 가져요. "경상북도 포항시 북구", "포항북구", `47113`이 같아지는 지점이 여기예요. 캔버스의 지역코드 정규화는 이 정보를 그대로 써요.

## 식별자 규칙

| 대상             | 형식                        | 예시                        |
| ---------------- | --------------------------- | --------------------------- |
| 시군구           | 행정표준코드 5자리 문자열   | `"47113"`                   |
| 기준 연도        | 4자리 정수                  | `2024`                      |
| 데이터셋         | `<출처>:<원본 ID>`          | `"data.go.kr:15012345"`     |
| 컬럼             | `<데이터셋 ID>#<원본 컬럼명>` | `"data.go.kr:15012345#시군구명"` |
| 개념             | `<role>:<kebab-case 이름>`  | `"key:sigungu"`             |
| 프로젝트         | ULID 26자 대문자 문자열     | `"01K39QW2M5B7X0YFTN4C8REJD1"` |

지역명 문자열은 저장하지 않고 표시할 때만 코드에서 변환해요. 코드를 문자열로 다루고 정수로 파싱하지 않아요. 앞자리 `0`이 사라져요.

## 안 쓰는 말

| 쓰지 않아요        | 대신                        | 이유                                          |
| ------------------ | --------------------------- | --------------------------------------------- |
| 파이프라인 실행 코드 | 연산 스펙                   | AI가 코드를 실행하지 않는다는 원칙을 흐려요   |
| 지역               | 시군구 또는 시도            | 범위가 모호해요                               |
| 검색               | 발견 또는 제안              | 키워드 매칭과 구분되지 않아요                 |
| 노드               | 그래프 노드 또는 캔버스 노드 | 서로 다른 두 개념이 같은 이름을 써요          |
| 태그               | 개념                        | 개념은 `role`을 가지고 조인 판정에 쓰여요     |
| 워크스페이스, 보드 | 프로젝트                    | 담는 단위는 하나이고 이름도 하나여야 해요     |
